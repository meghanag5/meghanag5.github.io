From mixed PDFs to usable information.

A Python document-intelligence pipeline combining OCR, layout-aware routing, structured extraction, and semantic retrieval.

The operational problem

Mortgage files can combine multiple document types, layouts, and scanned pages. Useful information needs to be extracted and organized before it can support search or downstream workflows.

I worked on the pipeline connecting document preprocessing to extraction and retrieval, with attention to OCR and classification bottlenecks.

My contribution

  • Built Python preprocessing, OCR, structured extraction, and semantic retrieval stages.
  • Developed layout-aware blob splitting and routing for mixed-document files.
  • Compared Tesseract, PaddleOCR, and EasyOCR for accuracy and latency.
  • Optimized batching and extraction logic after identifying OCR inference and classification bottlenecks.
  • Integrated LlamaIndex and refined retrieval through chunking and metadata filtering.

Pipeline architecture

  1. Preprocess PDFsPrepare unstructured mortgage documents for downstream processing.
  2. Recognize and routeRun OCR and use layout-aware splitting and classification.
  3. Extract and structureTransform document content into usable extracted information.
  4. Index and retrieveChunk content and apply metadata filtering for semantic retrieval.

Engineering tradeoffs

OCR accuracy versus latency

Comparing three OCR engines makes the choice measurable rather than assuming a single engine handles every layout equally well. I evaluated both extraction quality and latency.

Document boundaries before retrieval

Mixed files need useful boundaries and routing. Layout-aware splitting helps organize content before extraction and indexing, rather than treating every page as the same document type.

Optimize the bottleneck

I identified OCR inference and blob classification as key bottlenecks, then focused batching and extraction changes on end-to-end processing time.

Outcomes & evidence

Project outcomes included approximately 35% better document-processing efficiency, approximately 25–30% lower end-to-end processing time, and approximately 40% better retrieval precision through chunking and metadata filtering.

Approximate project-reported improvements. Benchmark inputs, measurement protocols, and private evaluation artifacts are not published here, so these figures should not be treated as independently reproducible benchmarks.

What this work demonstrates

Connecting multiple AI and software stages, evaluating alternatives, locating bottlenecks, and improving a business document workflow.

Further validation

To make a public version reproducible, I would use synthetic documents, a fixed extraction schema, labeled field-level examples, latency measurements, and a retrieval evaluation set. That public benchmark is not included in this case study.
